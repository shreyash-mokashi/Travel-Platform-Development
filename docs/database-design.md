# Voyago — Database design

Two stores. PostgreSQL 16 owns everything transactional; MongoDB 7 owns editorial content and
append-only snapshots. No transactional data is duplicated between them.

Canonical schema: [`apps/api/prisma/schema.prisma`](../apps/api/prisma/schema.prisma).

---

## Conventions

- **Primary keys** are UUIDs (`@db.Uuid`), generated by the application.
- **Money** is always `Int`, in minor units (paise). Never `Float`, never `Numeric`.
- **Calendar dates** (`checkIn`, `checkOut`, inventory `date`) use `@db.Date` and are handled as
  UTC midnight, so a stay never shifts with a timezone.
- **Timestamps** (`createdAt`, `updatedAt`) are `DateTime` with timezone.
- Table names are `snake_case` via `@@map`; model names are `PascalCase`.

---

## Entity relationships

```
User ──< Booking >── Hotel ──< Room ──< RatePlan >── CancellationPolicy
 │          │                   │
 │          │                   └──< RoomInventory      (one row per room per night)
 │          ├──< BookingGuest
 │          ├──< PaymentAttempt
 │          ├──< BookingStatusEvent
 │          └──1 Refund
 ├──< RefreshToken
 └──< Quote ──1 Booking                                 (a quote is single-use)

Destination ──< Hotel
Destination ──< Booking                                 (denormalised for admin reporting)
User ──< AdminAuditLog
```

## Tables

### `users`

| Column                  | Type  | Notes                                              |
| ----------------------- | ----- | -------------------------------------------------- |
| `id`                    | uuid  | PK                                                 |
| `email`                 | text  | **unique**, lower-cased on write                   |
| `passwordHash`          | text  | bcrypt, 12 rounds — never returned by any endpoint |
| `firstName`, `lastName` | text  |                                                    |
| `phone`                 | text? | optional                                           |
| `role`                  | enum  | `CUSTOMER` \| `ADMIN`, defaults to `CUSTOMER`      |
| `isActive`              | bool  | soft disable                                       |

Indexes: unique on `email`, index on `role`.

The registration endpoint never writes `role`; it is hard-coded to `CUSTOMER` in the service.
Admin accounts come only from the seed.

### `refresh_tokens`

| Column      | Type       | Notes                                                               |
| ----------- | ---------- | ------------------------------------------------------------------- |
| `tokenHash` | text       | **unique** — SHA-256 of the token; the token itself is never stored |
| `expiresAt` | timestamp  |                                                                     |
| `revokedAt` | timestamp? | set on rotation, logout or password change                          |

`onDelete: Cascade` from `users`. Indexed on `userId` and `expiresAt`.

### `destinations`

`slug` unique (`goa`, `mumbai`, …), plus `city`, `state`, `country`, `tagline`,
`heroImageUrl`, `isActive`. Indexed on `city`. Referenced with `onDelete: Restrict` — a
destination with hotels cannot be deleted.

### `hotels`

Identified by a unique `slug`. Carries `starRating`, `guestRating` (`Decimal(3,1)`),
`reviewCount`, address fields, `latitude`/`longitude` (`Decimal(9,6)`), check-in/out times, and
`amenities`/`policies` as `String[]`.

Indexes: `destinationId`, `starRating`, `isActive`.

`amenities` is a Postgres array rather than a join table. Amenity codes are a small fixed
vocabulary validated at the DTO layer; a join table would add a hop to every search with no
benefit at this cardinality.

### `rooms` and `room_images`, `hotel_images`

`rooms` holds occupancy limits (`maxAdults`, `maxChildren`, `maxOccupancy`), `sizeSqm`,
`bedType`, `amenities[]` and `totalRooms` (the physical count). Images cascade from their
parent and are ordered by `position`.

### `cancellation_policies`

| Column       | Type  | Notes                                                                |
| ------------ | ----- | -------------------------------------------------------------------- |
| `code`       | text  | **unique** — `FREE_48H`, `FLEX_24H`, `PARTIAL_72H`, `NON_REFUNDABLE` |
| `refundable` | bool  |                                                                      |
| `tiers`      | jsonb | ordered `[{ hoursBeforeCheckIn, penaltyBasisPoints, label }]`        |

Tiers are JSON because they are read as a unit, evaluated in application code, and never
queried field-by-field. Referenced with `onDelete: Restrict`.

### `rate_plans`

| Column                  | Notes                                            |
| ----------------------- | ------------------------------------------------ |
| `code`                  | unique **per room** (`@@unique([roomId, code])`) |
| `mealPlan`              | enum                                             |
| `discountBasisPoints`   | discount off the tariff                          |
| `supplementBasisPoints` | premium for meals or flexibility                 |
| `cancellationPolicyId`  | FK, `Restrict`                                   |

Pricing both axes is what stops every rate plan on a room costing the same.

### `room_inventory`

One row per room type per night — the heart of availability.

| Column            | Notes                                                                |
| ----------------- | -------------------------------------------------------------------- |
| `roomId` + `date` | **`@@unique([roomId, date])`** — makes an upsert safe and idempotent |
| `roomsOpen`       | physical rooms released for sale that night                          |
| `baseRateMinor`   | nightly tariff in paise                                              |

Indexed on `date`. The seed writes ~16,500 rows (69 room types × 240 nights).

A missing row means _not on sale_, which is different from `roomsOpen = 0` (_sold out_). The
availability query requires a row for **every** night of the stay.

### `quotes`

A server-issued price, and simultaneously a **soft inventory hold**.

| Column       | Notes                                                        |
| ------------ | ------------------------------------------------------------ |
| `totalMinor` | the authoritative total                                      |
| `breakdown`  | jsonb — the full `PriceBreakdown`                            |
| `expiresAt`  | 20 minutes from creation                                     |
| `consumedAt` | set when a booking is created; makes the quote single-use    |
| `userId`     | nullable FK, `SetNull` — anonymous visitors can price a room |

Indexed on `(roomId, expiresAt, consumedAt)`, which is exactly the availability lookup.

While `consumedAt IS NULL AND expiresAt > now()`, the quote's `rooms` subtract from
availability for every other caller.

### `bookings`

| Column                                    | Notes                                                                       |
| ----------------------------------------- | --------------------------------------------------------------------------- |
| `reference`                               | **unique**, `VYG-XXXXXXXX`, from an alphabet with no `I`/`O`/`0`/`1`        |
| `quoteId`                                 | **unique**, nullable — enforces one booking per quote at the database level |
| `status`, `paymentStatus`, `refundStatus` | enums                                                                       |
| `totalMinor`, `refundMinor`               | integer paise                                                               |
| `priceSnapshot`                           | jsonb — the breakdown, frozen                                               |
| `cancellationPolicySnapshot`              | jsonb — the policy as agreed                                                |
| `hotelSnapshot`                           | jsonb — name, address, phone, check-in times                                |
| `paymentDeadline`                         | 30 minutes from creation                                                    |

Indexes: `(userId, createdAt)` for history, `status` for admin filters, `hotelId`, and
`(roomId, checkIn, checkOut)` for the availability overlap query.

All parent relations use `onDelete: Restrict`. **A hotel or user with bookings cannot be
deleted** — financial records must not vanish because a catalogue row was removed.

The three snapshot columns are the reason a booking reads back correctly years later.

### `booking_guests`

Cascades from the booking. Only `firstName`, `lastName`, `isLeadGuest` and `position` — no date
of birth, passport number or address, because the demo has no use for them and storing
unnecessary personal data is a liability.

### `payment_attempts`

| Column           | Notes                                                                  |
| ---------------- | ---------------------------------------------------------------------- |
| `idempotencyKey` | **unique across the whole table** — the duplicate-submission guarantee |
| `scenario`       | `SUCCESS` \| `FAILURE` \| `PENDING`                                    |
| `status`         | `INITIATED` \| `PENDING` \| `SUCCEEDED` \| `FAILED`                    |
| `simulatorRef`   | a fake gateway reference; no real gateway exists                       |

**No card data is modelled, because none is ever collected.**

### `booking_status_events`

Append-only history: `fromStatus`, `toStatus`, `note`, `actorUserId`. Every validated
transition writes one, so a booking's full history is reconstructible.

### `refunds`

One per booking (`bookingId` unique): `status`, `amountMinor`, `penaltyMinor`, `reason`,
`requestedAt`, `settledAt`. Created only when a **paid** booking is cancelled.

### `admin_audit_logs`

`action`, `entityType`, `entityId`, `metadata` (jsonb), `actorUserId`. Indexed on
`(entityType, entityId)` and `createdAt`. The actor FK is `SetNull` so the log outlives the
account.

## Transaction boundaries

Three operations are wrapped in a transaction, each because a partial write would corrupt state:

**1. Booking creation**
Re-reads the quote inside the transaction, marks it consumed, and creates the booking, guests
and first status event together. The unique constraint on `bookings.quoteId` is the final
backstop against two bookings from one hold.

**2. Payment attempt**
Writes the `PAYMENT_PROCESSING` transition, the outcome transition, the `PaymentAttempt` row,
and the booking update as one unit. A booking can never be left in `PAYMENT_PROCESSING` with no
attempt recorded.

**3. Cancellation**
Updates status and refund fields, writes the status event, and upserts the `Refund` row
together.

Admin bulk inventory edits also run as one transaction across the date range.

## Migrations

Prisma Migrate, with SQL checked into `apps/api/prisma/migrations/`.

```bash
pnpm db:migrate    # create and apply during development
pnpm db:deploy     # apply existing migrations (production-safe)
pnpm db:reset      # drop, re-migrate, re-seed
```

Every migration is version-controlled. `db:deploy` never generates new SQL, so deployment is
deterministic.

## Seeding

`apps/api/prisma/seed.ts` truncates with `RESTART IDENTITY CASCADE` and rebuilds from scratch,
so seeding is idempotent.

It uses a **deterministic PRNG** — the same seed produces the same catalogue every run, which
keeps test expectations stable. Roughly 3% of nights are seeded as sold out so empty states are
reachable; weekends carry a 22% premium.

Demo passwords come from `SEED_DEMO_*_PASSWORD` if set, otherwise they are **randomly
generated and printed once**. Nothing is hard-coded, so an accidental production seed cannot
create a known-password admin account.

## MongoDB collections

### `destination_content`

Unique index on `destinationSlug`. Holds `headline`, `intro`, `highlights[]`,
`bestTimeToVisit`, `neighbourhoods[]`, `faqs[]`.

Nested, free-form, revised independently of the booking schema, never read in a transaction —
and if the collection is unavailable, hotel pages simply render without their guide.

### `supplier_snapshots`

Indexed on `correlationId` and `(kind, createdAt)`. Append-only record of exactly what the
pricing engine returned at quote and booking time.

Written **outside** the booking transaction and wrapped in `try/catch`: a logging failure must
never fail a booking.

```bash
pnpm infra:reset && pnpm db:deploy && pnpm db:seed
```

loads the demo dataset.
